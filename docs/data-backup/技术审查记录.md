# 备份恢复实现审查记录

2026-11-01。使用requesting-code-review技能进行独立只读审查，多轮复核后无未关闭的Critical/Important。未操作正式数据。

| 问题 | 修复与证据 |
| --- | --- |
| 清单仅信任ZIP声明尺寸，实际解压可超量 | 流式累计真实字节，4MB即中断；伪造声明1KB实际5MB测试 |
| 创建与导入JSON容量不一致 | 两侧单JSON32MB、核心总64MB一致；创建拒绝超限JSON |
| 清单过长可创建但不能导入 | 写ZIP前序列化字节检查4MB；15000长路径元数据测试 |
| 新服务已启动但事务未清理时误回滚 | 持久化prepared/original-kept/swapped/committed/rolled-back阶段；提交后仅清标记 |
| 活着的新服务仍在使用数据时移动目录 | pending记录serverPid，确认退出后才能回滚；未退出时保留维护状态 |
| spawn后PID日志写入失败绕过清理 | 所有spawn后异常统一停止并确认child退出；无法确认标记processAlive；新服务seed前登记PID |
| 准备安全备份或解压阶段崩溃任务永久running | 没有存活执行者且未替换目录时标记失败，明确原数据未变 |
| 重复安全回滚请求产生多个worker | current同步排他、pending持久化owner、worker明确自身身份；HTTP并发返回202/409 |
| 回滚完成仍提供重复回滚按钮 | 清recoveryRequired，真实安全重启完整终态测试 |

相关用例在check-backup-archive/service/recovery/http/ui脚本中。恢复状态需要由持久任务和事务标记共同判断，不以单次进程退出或一次健康响应代替事务提交。
