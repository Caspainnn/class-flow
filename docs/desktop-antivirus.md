# 桌面入口查杀排查与复测

2026-11-06：老师电脑的360截图显示“一堂课.lnk”被隔离，检测名称virus.lnk-powershell.a。开发机没有360；此文区分本地功能自测与老师电脑上的防病毒复测。

## 已有证据与处理范围

- 截图检测对象是桌面快捷方式，尚无证据表明截图检测对象是一堂课.exe、Node或WorkBuddy本体。
- 旧版tools/setup-desktop.ps1生成的快捷方式直接运行PowerShell，参数包含隐藏窗口、ExecutionPolicy Bypass和tools/open-desktop.ps1，符合需要优先排查的启动链。
- 当前源码改为快捷方式直接运行项目一堂课.exe，端口、数据目录、监听地址和学生访问地址由EXE参数接收。安装仍使用可阅读的本机脚本；后台服务启动仍有既有PowerShell辅助脚本。
- 这解决了当前快捷方式直接调用PowerShell的问题，不构成误报鉴定，也不保证360不会报告其他对象。

## 老师电脑复测

1. 先保留360检测名称、被隔离对象、发现时间及文件路径；隔离区原文件先保持原状。不要关闭360、添加整个项目到信任区，或反复恢复同一个旧快捷方式。
2. 获取GitHub main中包含本修复的项目版本，核对tools/setup-desktop.ps1已将快捷方式TargetPath设置为exe，且tools/launcher.cs支持--data-dir等参数；记录实际更新的提交号。本次交付为源码更新，旧发行包不自动包含修复。按README“交给Agent自动检查与更新”保留原数据、配置和本地改动，检查所有教学与后台任务空闲、备份后再安全退出托盘。不要覆盖在用EXE或中断教学任务。
3. 保留原PORT、绝对DATA_DIR、HOST及PUBLIC_ORIGIN，运行修复版tools/setup-desktop.ps1重新构建并创建入口，参数按老师电脑实际值填写。截图中的原快捷方式已被隔离时，也可由脚本重新生成；无需恢复旧快捷方式。不得使用开发者电脑的数据目录。先不加-Open，便于检查新入口和360结果。
4. 右键新桌面“一堂课”→属性：目标应为项目中的一堂课.exe，附带--port、--data-dir、--host、--public-origin参数；不应以powershell.exe为目标，也不应包含-ExecutionPolicy Bypass或open-desktop.ps1。
5. 在360保持正常防护的状态下，按其界面扫描新入口及程序目录，再双击入口。分别记录“扫描时”和“双击启动时”是否拦截，以及360实际报告的对象和检测名称。
6. 未被拦截后检查平台打开、托盘可见、原教学数据仍可读取；重复双击应复用同一服务并打开网页，不创建测试课程或签到。日志需出现本次ready和browser opened。只有老师电脑实际完成检查，才记录该机该次360复测通过。

## 若仍被拦截

保留新一轮截图或360检测日志，并记录360版本、病毒库版本、扫描或启动哪个步骤触发、实际文件名/路径和检测名称。新入口仍被拦截与EXE/后台脚本被拦截需要分别定位；不要仅凭同一个产品名归为同一问题。

若需要向360申请误报复核，先核对文件来自可信项目构建，按官方入口仅提交必要的程序样本或快捷方式及说明；不得附带教学data、备份、账号目录或密钥。未取得复核结论前，继续保留“原因待确认”状态。
