# 首页与结尾页独立记录

用户确认：模板按原稿第一/最后一页直接定位首页和结尾页，两者不参与通用布局合并；结尾页采用专属简短回顾规范，不增加识别/确认流程。

## 实现

- 模板add/analyze提取pageRoles.cover、ending，记录sourceSlide与专用layoutId，另生成roles/<hash>.pptx。两页相同排版也分别保留来源；只有1页原稿时物理文件只含1页，但保留两项用途。
- 原模板和原通用布局文件仍保留，不自动覆盖已选任务快照。旧库模板下次解析补充角色记录；任务选择模板时复制独立角色文件与元数据。历史任务仍使用原先快照。
- 管理页单独展示首页/结尾页卡片，支持查看原PPT；通用布局计数另列。若智能分组把首页、正文和结尾归为同组，通用卡片改用组内正文页作代表，不因首尾独立而丢失可编辑的正文布局。
- 逐页制作先/末页直接用专用PNG与profile，不让模型重新判断用途。PNG由本机PowerPoint渲染，专用截图输出到template-special-pages以免覆盖通用截图。逐页修改首页/尾页同样使用对应专用截图；1页成品优先首页。
- endingRules规范2–3个简短本课结论、可选一句收束语/致谢/欢迎提问；不显示课时或适用对象，不默认复制教师信息/联系方式/下节预告/模板旧结论和长串来源。真实引用保留在已安排参考页或讲稿。原末页若有实质教学内容，在大纲中先安排保留位置，不为结尾漏步骤/例题/数据。
- 新规则作用于新大纲/新制页面，导出仍只转换已确认HTML；续做不改写已完成页。现有导出任务不因本功能中断。

## 验证

check-ppt-template-management：两页相同布局仍分别记录首尾，角色PPTX实际2页；通用精简文件仍按原选择页数；任务角色快照在库删除后不变。
check-ppt-template-pages：单页模板角色双用途、物理一页；生成首尾选择cover/ending，结尾带专属规则；逐页修改、取消及视觉失败回归。
check-ppt-template-management-ui：专用角色之外保留智能组内正文代表，继续支持手动补页和未保存状态；check-ppt-cover-rules覆盖结尾规则与导出不改稿；HTML/update/resume等回归。全部使用隔离数据和模型替身，没有真实模型出片验证。
