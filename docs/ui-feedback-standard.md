# 交互反馈规范

适用于一堂课所有新增及修改的页面、原型。2026-10-27 根据用户要求建立。既有页面在对应功能迭代时按此修正；本文不代表全部旧页面已完成改造。

## 依据与选择原则

参考 [Ant Design Modal](https://ant.design/components/modal/)、[Message](https://ant.design/components/message/)、[Alert](https://ant.design/components/alert/)、[Notification](https://ant.design/components/notification/)，以及 [Atlassian Banner](https://atlassian.design/components/banner/usage) 和 [W3C 模态对话框规范](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)。以下是结合课堂场景制定的项目约定，不是某一外部标准的逐字复刻，也不要求安装组件库。

同时判断三件事：后果是否严重、是否需要立即决策、影响范围在哪里。颜色表达状态，承载方式表达用户需要怎样响应；不能把所有错误都做成弹窗，也不能仅按红黄蓝机械分级。

| 场景 | 承载方式 | 保留与操作规则 | 项目例子 |
| --- | --- | --- | --- |
| 某项输入需修正 | 输入框附近的行内校验 | 修正前保留；定位到首个错误；保留已填内容 | 未选择课程、缺少正确答案 |
| 简短结果，无需进一步操作 | 轻消息 Message / Toast | 通常约 3 秒；不抢焦点；同一结果不重复提醒 | 已复制、已保存、已取消 |
| 当前任务遇到需处理的问题 | 对应区域内的 Alert | 持续显示至解决；说明原因及下一步，提供重试/配置入口 | 交接失败、附件不支持、取消请求失败 |
| 后台异步结果或较复杂的提醒 | 通知 Notification | 可带“查看结果”；需行动或失败的通知不自动消失；任务列表保留状态 | 老师切到其他页面后课件制作完成 |
| 影响整个平台使用 | 页面顶部 Banner | 同时只展示一个首要问题；不覆盖内容；故障解决后撤下；必要信息不可随意关闭 | 本地服务离线、存储不可写 |
| 继续前必须明确决定，或将丢弃数据/中断任务 | 确认弹窗 Modal | 明确对象与后果，安全操作和风险操作分开；确认成功后关闭 | 取消正在进行的签到、停止本轮课件制作、删除课程 |

低风险、可撤销的操作可直接执行并给撤销入口，避免层层确认。普通“取消编辑/关闭窗口”若无未保存内容，使用中性按钮；会终止任务或丢弃记录的“取消”使用危险按钮。普通提示不要滥用顶部横幅。

## 颜色、文案与位置

- 正常主操作沿用蓝色；安全返回/继续使用中性按钮。危险操作入口及确认按钮使用白底红框红字：文字 `#b42318`、边框 `#d92d20`，悬停浅红底 `#fff1f0`。严重不可恢复删除可使用实心红，但同一流程保持一致。
- 成功用绿色，需注意用琥珀色，失败/危险用红色，一般信息用蓝色；同时给文字或图标，不仅靠颜色表达含义。
- 按钮写明确动词和对象，例如“继续签到”“确认取消并返回选题”，避免“确定/取消”互相歧义。提示写清发生了什么、影响什么、下一步怎么做，不展示内部报错栈。
- 本项目轻消息沿用底部居中；顶部 Banner 属于页面布局的一部分。轻消息、通知、局部提示各有用途，禁止同一事件同时弹出三种提示。
- 流程的“上一步”放在内容底部左侧；风险操作不与“下一步”使用同一主色。

## 确认弹窗必须满足

1. 标题明确，正文说明影响和保留内容。签到取消须说明二维码/课堂码失效、空记录移除、不计入统计。
2. 使用原生 `dialog.showModal()` 或具备同等可访问性的组件。关联可见标题；打开后焦点进入弹窗，风险确认默认聚焦安全操作；Tab 留在弹窗内，关闭后回到触发点或合理的下一操作。
3. Escape 和安全按钮只关闭确认、不执行业务取消；点击遮罩不得确认危险动作。提交中禁用重复操作，必要时阻止 Escape，避免请求结果与页面状态脱节。
4. 请求失败在弹窗内持续显示原因，保留上下文和重试入口。只有成功后才更新业务状态，成功反馈不再额外弹窗。
5. 确认期间实时校验前提，服务端最终校验。签到若已有人提交必须禁止取消，不能仅靠前端按钮保护。

## 开发验收

新增或改动反馈时，检查：承载方式是否匹配影响范围；风险按钮与主操作是否区分；弹窗是否支持键盘；错误是否持续可见并保留输入；提交是否防重复；失败与并发变化是否正确处理。无需业务接口的视觉调整不得操作真实教学数据。

本轮落地：签到取消入口及确认改为红框，行内确认改为模态弹窗，取消失败留在弹窗内；PPT 原型停止制作入口及确认同步使用红框。其他既有提示的逐项迁移随相关功能迭代执行。
