# 平台数据看板规划

日期：2026-11-01。状态：建议方案，待用户审阅；尚未修改导航、业务页面或真实教学数据。

## 1. 定位与范围

在侧栏“概览”分组中，将“数据看板”放在“工作台”下方，作为平台统一统计入口，替换“学情分析”的旧数据看板。工作台继续负责快捷操作与近期事项；新看板负责跨课程统计、趋势、课程比较与问题定位。

用户已明确：全平台关键数据尽可能覆盖；原“预警名单、个体画像、练习分析、问卷管理”保留。本文件中的布局、指标优先级与口径修订均为建议，未经确认不视为已批准实现。

推荐采用“综合概览 + 分类分析页签”。一个页面堆满所有指标会过长；完全拆成独立模块又难以总览。概览展示核心指标和教学趋势，分类页签承接深度分析，并链接回业务页面处理。

建议页签：综合概览、课堂参与、作业与批改、问卷反馈、备课资源。学情关注在概览展示汇总及入口，详细分析复用已有学情模块。

## 2. 页面结构

1. 顶部：标题、课程筛选（默认全部）、学期筛选、活动日期（近7天、近30天、自定义、全部）、更新时间、刷新。
2. 首屏六项概览：课程数、课程名单人数、签到场次、课堂参与率、待处理事项、问卷答卷数。每张卡明确单位及范围，可点击进入对应分类。备课产物数量在资源分区完整展示，避免首屏塞入十余张卡。
3. 教学参与趋势：出勤率、答题参与率、答对率；使用同一时间轴，缺数据留空，不补零。支持按周汇总和最近课次。
4. 左右分区：课程比较表、待处理事项。比较表含名单人数、签到场次、出勤率、作业记录和问卷回收；默认按课程名称排列，不设置“最好/最差课程”排行榜。
5. 概览下半部：作业与批改摘要、问卷回收摘要、备课资源摘要、学情关注摘要。用图表和紧凑列表呈现，详细信息进入分类页签或原模块。
6. 页面顶部与页签位置固定；切换页签不因标题、容器宽度或滚动条变化左右浮动。窄屏改为上下排列。

课程数、名单人数与模板库存是“当前存量”，不随活动日期变化，旁注“当前”；签到、答卷等是“所选期间活动”。预警为当前规则下的课程全量结果，旁注“当前课程全量”，不能伪装成筛选期间预警。

## 3. 指标清单与现有数据依据

可直接算：现有持久化字段足够，仍需新增统一聚合接口；不等于现有页面已经按本规划实现。需补采集：先建后续记录机制，不回填猜测值。暂不支持：当前无法给出可信结论。

| 分类/指标 | 公式或口径 | 数据来源 | 可用性与限制 | 点击去向 |
| --- | --- | --- | --- | --- |
| 当前课程数 | 非删除课程数，按所选课程/学期过滤 | `server/lib/courses.js`，`courses` | 可直接算；不是期间新增课程数 | 课程管理 |
| 课程名单人数 | 各课程当前名单人数之和 | `students`、课程列表 | 可直接算；跨课程同一学生重复计数，单位注明“人次” | 课程名单 |
| 全校唯一学生数 | 经可信统一身份去重 | 当前只有课程名单 | 暂不支持；不默认将同名或跨课程同学号合并 | 暂不展示 |
| 签到场次 | 期间内有有效记录、已结束的签到数；进行中另列 | `server/server.js`，`sessions.startedAt/closed/endsAt/records` | 可直接算；一次点名不等同完整一次授课，名称保持“签到场次”；已结束空记录另显示，不进入参与率 | 签到管理 |
| 出勤人数/人次 | 每场按课程名单有效studentId去重，汇总人次 | `sessions.records`、当前名单 | 可直接算；历史名单限制见下文 | 对应课堂记录 |
| 出勤率 | 到课人次合计 / 应到人次合计 | 同上 | 可直接算当前名单口径；跨课次不平均百分比 | 课堂参与 |
| 迟到/缺勤 | 迟到属于到课；缺勤=应到−到课 | `records.status` | 已结束场次可算；进行中仅显示“尚未签到” | 对应课堂记录 |
| 答题参与率 | 有有效答案人次 / 应到人次 | `server/lib/answers.js`判定逻辑、records | 可直接算；不能用签到人数直接替代有效作答人数 | 练习分析 |
| 答对率 | 答对人次 / 有效作答人次 | `records.correct/answer` | 可直接算；不要沿用旧看板对各课次正确率简单平均的做法 | 练习分析 |
| 作业数 | 非删除作业，关联批次不重复计数；区分草稿/已归档成绩 | `server/lib/homework.js`，`homework/gradebatches` | 可直接算；“published”不能视为学生在线收作业的证据 | 作业管理 |
| 已录分/未录分人数 | 有有效成绩的名单成员 / 其余名单成员 | `scores`、`manualMissing` | 可直接算；未录分不自动等于未交，显式标记未交单列 | 作业详情 |
| 已匹配作业文件人数 | matched文件按有效sid去重 | `server/grade/grade.js`，`batch.files` | 可直接算；是教师导入的文件，不等同学生在线提交；多文件不能多计人数 | 自动批改 |
| 待匹配/异常/待批改 | 未匹配文件数、异常结果数、已匹配但无有效结果的学生数 | `files/results/abnormal` | 可直接算；三种状态分别显示 | 批改对应批次 |
| 运行中/已产出/已归档批次 | 当前批次状态分布 | `batch.status` | 可直接算；done表示已产出，不代表全部教师审阅 | 自动批改 |
| 成绩均分/分布 | 有效成绩换算百分制后按作业统计，缺失不计零分 | `scoresOf()`、`rawTotal/rawMax` | 可直接算；课程默认展示各次作业趋势，不混合不同作业直接比较教学质量 | 作业分析 |
| 学生在线提交率/准时率 | 需独立提交与时间记录 | 当前批改上传为教师导入 | 暂不支持；不能复用现有API中submitted字段充当学生提交人数 | 暂不展示 |
| 当前关注学生 | 每门课程内触发既有规则的学生去重；全平台显示“课程关注人次” | `xueqing/xueqing.js`，`students.warns` | 可直接算；显示规则名、范围，不生成能力综合分 | 预警名单 |
| 关注原因分布 | 按规则计命中数，同一人可命中多项 | 同上 | 可直接算；不应将原因总数当学生人数 | 预警名单 |
| 发布/回收中/结束/归档问卷 | 按问卷状态分别统计 | `server/questionnaire/service.js`、model.closed | 可直接算；到期派生结束，归档单列 | 问卷管理 |
| 期间答卷数/趋势 | submittedAt在所选期间的答卷份数 | `responses.submittedAt` | 可直接算；跨问卷是份数，不是唯一参与学生数 | 问卷结果 |
| 实名回收率/未提交 | 单份问卷有效实名答卷数 / 发布时target名单人数 | `target`、responses.studentId | 可直接算；总览可按分母加权，注明问卷人次，不是唯一学生覆盖率 | 实名未提交表格 |
| 匿名问卷回收 | 有效答卷份数 | anonymous responses | 可直接算；不显示未提交名单、可靠去重学生数或实名式回收率 | 问卷结果 |
| 逐题分布 | 单选/量表按有效作答，多选区分作答人数与选择次数 | questionnaire model与dashboard | 可直接算；柱图与环图左右同时展示；开放文本默认只给查看入口 | 逐题分析 |
| 问卷情绪/满意度总分 | 需明确量表、题意、评分及可比较范围 | 当前不同问卷不具统一尺度 | 暂不支持跨问卷统一评分；不把主观反馈纳入能力预警 | 暂不展示 |
| PPT课件/HTML成品/导出数量 | 任务数、存在HTML版本的任务数、存在PPTX版本的任务数分别计算 | `server/ppt/service.js`，htmlVersions/versions | 可直接算；同一任务多版本不重复算多份课件 | PPT管理 |
| PPT当前可用产物 | 当前要求下的最新HTML/导出产物，与旧版本保留区分 | requirementsRevision/hash/approvedHtmlVersion/reviewedVersion | 可直接算；旧成品仍在时，新一轮可能失败，不能简单把任务失败等于没有课件 | 对应课件 |
| 教案/Word版本 | 任务数、有有效Word版本的任务数、版本数分列 | `server/lesson-plan/service.js`，versions | 可直接算；complete不自动代表教师审阅通过 | 教案制作 |
| 模板库存/布局数/使用情况 | PPT模板、确认布局数、引用模板的课件任务数；教案模板单列 | `server/ppt/templates.js`、template.profile、教案templates | 可直接算；内置/上传模板分开；模板是全局资源，不强行归课程 | 模板管理 |
| 当前制作任务/失败任务 | PPT、教案、问卷生成任务当前状态 | 各service与questionnaire/generator.js | 可直接算；失败不等于永久无产物，取消不算失败；问卷生成任务不含个人答卷 | 对应制作任务 |
| 制作成功率/平均耗时/节省时间 | 需稳定的逐次运行终态与起止日志 | 现有任务多保留最新run及版本 | 暂不做历史成功率/节省时间；完整运行事件需补采集 | 暂不展示 |
| 服务可用性 | 配置是否齐全，不代表已登录或模型服务实时在线 | `/api/ppt/connection`、教案/CLI配置 | 只显示必要的“待配置”等提示；不在看板自动调用模型做探活 | WorkBuddy设置 |

## 4. 统一统计规则

- 默认全部课程；课程筛选只包含有效课程。PPT、教案已有courseId，但未关联课程的历史资源放“未关联课程”，不得按标题猜测关联。课程单选时排除无关联资源并标注；全平台备课分区保留它们。
- 学期目前是课程上的文本，不是统一起止日期。学期筛选先按课程term分组，缺失归“未设置”；活动日期独立，不自动猜学期日历。
- 课程数、名单数、模板数为当前库存；期间新增课程用createdAt；课堂用startedAt；作业新增用createdAt；问卷发布用publishedAt；答卷用submittedAt；备课产物用版本createdAt。updatedAt不能替代完成时间。
- 签到记录目前没有名单快照，历史统计只能按当前课程名单重算。必须标“按当前名单统计”；本次规划建议后续为新签到保存名单快照，历史不回填。当前名单为空的课堂不进入比例分母，显示无法计算；不把它计作0%。
- 已结束空签到单独列出，不用来推断全班缺勤；取消移除的签到不进入任何统计；进行中场次不进入稳定历史趋势。未来若有完整授课实体再统计“授课课次”。
- 比例用总分子/总分母加权，显示样本量；分母为零显示“— / 暂无有效数据”。零是真实数，加载失败不是零，图表缺点不连成虚假下降。
- 课程删除后，默认统计排除该课程及其关联数据；作业删除按deletedAt排除；问卷归档保留历史答卷、排除回收中数量。未建立独立删除审计时，不承诺“当时全平台库存”的历史还原。
- 预警沿用现有规则，但旧规则有“无成绩视作未交”历史行为。新看板不直接将该原因转换成已核实未交人数；显示“按现有规则触发”，后续单独修订预警口径并验收。
- 临时测试数据不应进入正式源；测试必须使用独立DATA_DIR。正式聚合读服务层，不扫描临时目录或示例文件。

## 5. 分类页面重点

| 页面 | 建议图表/内容 | 操作 |
| --- | --- | --- |
| 综合概览 | 六项核心指标、参与趋势、课程比较、待办、四类摘要 | 选课程、进入分类或业务详情 |
| 课堂参与 | 到课/迟到/缺勤分布、三条参与趋势、课堂记录表、有效样本量 | 跳签到详情、练习分析 |
| 作业与批改 | 已录分/未录分/显式未交、批改状态、异常列表、逐次成绩分布 | 去匹配文件、继续批改、查看成绩 |
| 问卷反馈 | 回收中问卷、期间答卷趋势、实名回收进度、匿名份数、最近问卷 | 查看逐题图表、未提交表格；不在概览展开原始开放反馈 |
| 备课资源 | PPT/教案产物数量、正在制作/失败/待核对列表、真实课件封面、模板库存 | 打开对应任务或模板；不复制整套制作编辑器 |

全屏展示作为后续可选功能：教师私有分析页可显示姓名；课堂投影模式默认隐藏姓名、学号、原始文本反馈和个体预警，仅呈现聚合。是否首版增加投影模式待用户确认，首版默认仍为教师端页面。

## 6. 技术与迁移建议

- 新页面建议`/dashboard`，sidebar active key独立；同步shell.js、workspace.js、workspace.html中的允许路由与移动导航。纯规划阶段不改上述文件。
- 新增只读、教师端聚合接口，复用服务层，不由浏览器下载全量学生作答后拼接。返回筛选范围、生成时间、每项分母、数据限制与分区错误；后台不调用WorkBuddy生成统计。
- 现有`/api/questionnaires/overview`要求courseId，且仅最近5份问卷；新全局统计需单独服务聚合，不能把五份最近问卷相加冒充全量。
- 现有`/api/xq/data`包含课程全量预警与简单平均正确率，新看板需明确的新聚合逻辑，不在替换UI时悄悄沿用不一致口径。保留旧预警模块行为，另列修订事项。
- 旧`/xueqing?tab=dash`以及既有分享/收藏入口重定向或兼容导航到新看板；保留courseId，参数需校验。学情分析主入口默认进入预警名单，其他三个子模块保留，去掉重复“数据看板”子项。
- 请求切换使用最新请求校验，防止慢响应覆盖新课程；刷新失败显示局部提示与重试、保留最后成功数据及时间。后台任务通知沿用平台通知规范，不弹重复消息。
- 原型可用隔离虚构数据，标明示例；正式版必须复用真实源，禁止以演示指标补齐缺项。

## 7. 交付顺序及验收

1. 本轮：数据规划审阅，确认分区与优先级。
2. 原型：全局概览、分类页签、筛选、空态、异常态及课程下钻；旧页面保持可用。
3. 正式：只读聚合、口径测试、导航替换及旧链接兼容，再考虑历史名单快照等补采集。
