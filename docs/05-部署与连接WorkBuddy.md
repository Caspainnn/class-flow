# 部署与连接本地 WorkBuddy

这份文档只有一件事要讲清楚：**老师拿到 GitHub 上的项目后，怎么让 WorkBuddy 自己把平台装好，并自动连上 WorkBuddy 来做作业批改。**

装完的效果是：桌面一个图标，双击进去，侧栏底部显示绿点「本地 WorkBuddy 已连接」，作业批改可以直接用。

---

## 0. 先看这张图，知道有几块东西

```text
┌─────────────────────── 老师的 Windows 电脑 ───────────────────────┐
│                                                                  │
│   GitHub ──clone──▶  D:\ClassFlow        （平台本体，Node 进程）    │
│                          │                                       │
│                          │  ① 探测：找到并试通 WorkBuddy 自带的命令  │
│                          ▼                                       │
│   WorkBuddy（桌面版，已登录）                                     │
│        └─ 自带的非交互命令 codebuddy ──▶ 批改作业                  │
│                          │                                       │
│                          └─ ② 回写：分数存进 D:\ClassFlow\data\    │
│                                                                  │
│   浏览器 ──▶ http://127.0.0.1:3000/  ← 老师日常就用这个            │
└──────────────────────────────────────────────────────────────────┘
```

三块东西，缺一样会降级：

| 有什么                  | 能用到什么                          |
| --------------------- | ------------------------------ |
| 只有平台                  | 签到、学情分析、手动调用 WorkBuddy（自己去 WorkBuddy 里批，再把 Excel 拖回来） |
| 平台 + WorkBuddy 已登录    | 上面全部，**外加一键直批作业**              |
| 平台 + WorkBuddy 但连不上   | 全部退回手动调用，功能不受影响，侧栏显示琥珀色     |

这就是「推荐 + 保底」两条路：**连上了用直批，连不上用手动调用，任何一种都不会让老师卡住。**

## 1. 你要做的：把项目传到 GitHub

这一步只做一次。

### 1.1 确认不该上传的东西没被带上

项目自带的 `.gitignore` 已经挡住了这些，但值得你知道为什么：

| 目录 / 文件        | 为什么不能上传                                    |
| -------------- | ------------------------------------------ |
| `data/`        | 里面有真实学生名单，还有 `data/.secret`（签到码的签名密钥）。**传上去等于把全班名单公开** |
| `logs/`        | 运行日志，含访问记录                                 |
| `*.exe`、`dist/` | 打包产物，几十 MB，GitHub 仓库不该放二进制                   |
| `.workbuddy/`  | 开发过程记录                                     |

如果之前在别的地方手动放过这些东西，推之前先跑一次：

```bash
git status --short
```

看到 `data/` 或 `*.exe` 出现在待提交列表里，说明 `.gitignore` 没生效，先别推。

### 1.2 推送

```bash
git add .
git commit -m "docs: 新增部署与 WorkBuddy 连接说明"
git push
```

老师那边以后拿到的就是这一份。**你不需要真的推，这条命令写在这里是为了让文档自洽**——如果老师是直接从你本机拷过去，跳过这一节，从第 2 节开始。

### 1.3 仓库里要有这几样（否则老师装不上）

```text
ClassFlow/
├─ server/
│  ├─ server.js          ← 服务入口，默认监听 3000
│  ├─ package.json       ← 依赖只有 exceljs、qrcode
│  └─ lib/store.js
├─ xueqing/              ← 学情分析模块
├─ 课中签到.bat           ← 双击启动（源码版）
├─ 停止课中签到.bat        ← 双击停止
└─ tools/
   ├─ launcher.py        ← 打包 exe 用
   ├─ build.bat          ← 打包脚本
   └─ connect-workbuddy.js  ← ★ 新增：探测本地 WorkBuddy 并写入连接配置
```

## 2. 老师要做的事：把这一段发给 WorkBuddy

老师不需要看懂任何命令。**打开 WorkBuddy，把下面整段复制进去**，它就会自己一步步做。

> 复制范围从「```text」下一行开始，到「```」上一行为止。

```text
帮我把 ClassFlow（课堂工具平台）装到这台 Windows 电脑上，并连上你（WorkBuddy）自己，
让我以后能在这里直接批改学生作业。我是一线教师，不懂命令行，每一步做完用一句话
告诉我结果就行，遇到问题先自己排查，实在不行再问我。

按下面顺序做：

一、环境
1. 运行 node -v，需要 18 或更高。没有就装：
   winget install OpenJS.NodeJS.LTS
   没有 winget 就从 https://nodejs.org 下 LTS 安装包，装完重开终端再验证。
2. 确认有 git。没有的话，用 zip 代替 clone：
   https://github.com/Caspainnn/class-flow/archive/refs/heads/main.zip

二、放在哪儿
3. 选短路径，比如 D:\ClassFlow。
   不要放 C:\Program Files（要管理员权限，程序写不了数据），
   也不要放 OneDrive 同步目录或桌面深层目录。

三、装依赖
4. cd D:\ClassFlow\server
5. npm install --omit=dev
   如果卡住，换镜像：npm config set registry https://registry.npmmirror.com

四、先跑起来看看
6. node server.js
   看到 http://127.0.0.1:3000/ 就算成功，这个窗口先别关。
7. 浏览器打开 http://127.0.0.1:3000/ ，检查这几个页面都能正常打开：
   /           工作台
   /session    发起签到
   /join       学生端
   /admin      后台
   /xueqing    学情分析
   有打不开的，把终端报错发我。

五、连接 WorkBuddy（这一步是本轮的重点，别跳）
8. 在 D:\ClassFlow 下执行：
   node tools\connect-workbuddy.js
   这个脚本会依次找几个位置的 WorkBuddy 命令，试跑一次很短的请求，
   通了就把结果写进 data\settings.json 的 workbuddy 段。
9. 如果脚本报「未找到」，按它打印的提示做：
   - 用 where /r "C:\Program Files" codebuddy 之类的命令帮我找一下；
   - 或者问 WorkBuddy 的安装目录在哪儿，再手动指定：
     node tools\connect-workbuddy.js --path "找到的完整路径"
   - 找到了但试跑失败，把脚本输出的那段错误原样发给我，不要自己反复重试超过 2 次。
10. 连上之后，重启服务（先关掉第 6 步那个窗口，再 node server.js），
    打开 http://127.0.0.1:3000/ ，左侧栏底部应该显示绿点「本地 WorkBuddy 已连接」。

六、做成双击就能用
11. 在 D:\ClassFlow 下执行 tools\build.bat，产出 课中签到.exe
    （这一步需要 python 和 pyinstaller；装不上就跳过，直接用 课中签到.bat 也行，
     告诉我跳过了。）
12. 执行 python tools\make-shortcut.py 生成桌面快捷方式。
13. 关掉终端窗口，双击桌面图标，确认：服务能起来、浏览器能打开、
    侧栏底部还是绿点。

七、换成我的课程和名单（这一步要问我）
14. 先问我：课程叫什么、学期是什么、学生名单怎么给我。
15. 在 http://127.0.0.1:3000/admin 的「课程管理」里改课程名，
    名单可以粘贴（每行「学号 姓名」，空格逗号都行）或上传 xlsx。
16. 灌完确认显示的人数和我学生人数对得上。

八、最后给我三样东西
17. 桌面图标叫什么名字；
18. 启动日志里那行局域网地址（形如 http://192.168.1.5:3000），我上课投影要用；
19. 提醒我两件事：手机和电脑要连同一个 Wi-Fi；第一次启动 Windows 会弹防火墙，
    要点「允许」。

最后再确认一遍这四件事：
- data 目录里是我的真实名单，不要上传到任何地方，也不要提交到 git。
- 不要把项目放进 C:\Program Files 或 OneDrive。
- 连不上的时候不要硬改代码，先告诉我，我们改用手动调用。
- 改任何文件前先备份，改完告诉我改了哪几个。
```

走完这一趟，老师手上就是一个桌面图标、一个绿点，和一屋子学生能扫的二维码。

## 3. 连接到底怎么判定的

这一节是给你（维护者）看的，也是给愿意深究的老师看的。

### 3.1 为什么不用 API Key

| 方案                   | 谁付钱        | 学生作业去哪        | 稳定性           |
| -------------------- | ---------- | ------------- | ------------- |
| 平台填 API Key          | 老师按量付费     | 第三方模型厂商       | 稳，但要注册充值      |
| **连本地 WorkBuddy**    | **老师已有额度** | **在 WorkBuddy 里** | 依赖装的是哪一版，会漂   |
| 手动调用（老师自己开 WorkBuddy） | 老师已有额度     | 同上            | 最稳，永远可用 |

WorkBuddy 桌面版自带一个非交互命令，路径形如：

```text
<WorkBuddy 安装目录>\resources\app.asar.unpacked\cli\bin\codebuddy
```

它是桌面版 AI 的同一个内核，所以只要老师装了 WorkBuddy 并登录过，不用再花一分钱。代价是：**这是内部路径，不保证跨版本不变**。所以整套设计必须是「探测 → 试通 → 失败就降级」，不能把主流程压在这条路上。

### 3.2 探测顺序

`tools/connect-workbuddy.js` 按这个顺序找，第一个试通的胜出：

| 顺序 | 位置                                                  | 说明                          |
| -- | --------------------------------------------------- | --------------------------- |
| 1  | `settings.json` 里已存的路径                              | 上次连上的，优先复用，避免每次都全盘找         |
| 2  | 环境变量 `CODEBUDDY_CODE_PATH`                          | 高级用户手动指定                    |
| 3  | `%LOCALAPPDATA%\Programs\WorkBuddy\...\cli\bin\codebuddy` | 当前用户安装                      |
| 4  | `C:\Program Files\WorkBuddy\...\cli\bin\codebuddy`  | 全局安装                        |
| 5  | `D:\`、`E:\` 等盘符下 `WorkBuddy` 目录（深度 3 层）             | 老师常见的自定义安装位置                |
| 6  | `cli\dist\codebuddy-lite-wb.mjs`（同级兜底）               | 新版可能换文件名，两条都试               |

每个候选都要**真正跑一次**才算通过，判据是：

```bash
codebuddy -p "回复：OK" --output-format text --tools "" --permission-mode dontAsk
```

15 秒内返回、且输出里带 `OK`，才算连通。跑不动、超时、报错，都记下原因继续找下一个。

**这一步不能省。**文件存在不等于能用——实测中遇到过路径对、但启动就卡住的情况。只检查文件存在，老师点「批改」时会静默失败，那种体验比直接显示「未连接」糟糕得多。

### 3.3 写进哪儿

探测结果写到 `data\settings.json` 的 `workbuddy` 段：

```json
{
  "workbuddy": {
    "enabled": true,
    "path": "C:\\Program Files\\WorkBuddy\\resources\\app.asar.unpacked\\cli\\bin\\codebuddy",
    "version": "3.2.1",
    "model": "default",
    "timeoutMs": 60000,
    "verifiedAt": "2026-10-23T11:52:00.000Z",
    "lastError": null
  }
}
```

`data/` 不进 git，所以每台电脑各存各的，互不干扰。

### 3.4 界面上怎么体现

- **侧栏底部**：绿点「本地 WorkBuddy 已连接」/ 琥珀点「未连接 WorkBuddy」。点一下进设置。
- **作业批改第 3 步**：连上时默认选「平台调用 WorkBuddy」；未连接时这张卡变灰，光标自动落到「手动调用」。
- **设置里**：显示检测到的路径、版本、延迟，可以「重新检测」或「手动指定路径」，可以断开。
- **绝不弹报错框**。连不上只是状态变灰，加一行「WorkBuddy 升级后如果这里显示未连接，点重新检测就行」。

### 3.5 降级不是失败

这是整份文档最想说清楚的一点：**连不上 WorkBuddy，平台的作业批改功能照样完整可用。**

手动调用这条路，平台会替老师做掉三件最容易错的事：

1. 把收到的作业**按「学号+姓名」重命名**（老师原文件名经常是 `作业_最终版(1).pdf`）；
2. 识别不出的收进 `_待确认\`，没交的收进 `_未交\`；
3. 把提示词**连题目分值、评分尺度一起生成好**，老师只要粘贴 + 回车。

批完把 Excel 拖回平台，复核、改分、归档、进学情分析，全都一样。

## 4. 出问题怎么查

### 4.1 侧栏显示「未连接 WorkBuddy」

按顺序试：

1. 设置弹层里点「重新检测」，等 15 秒；
2. 确认 CLI 自身取得有效登录身份；桌面版已登录不代表独立 CLI 已登录。2026-10-23 实测及升级验证点见 [直连排查结论](07-WorkBuddy直连排查结论.md)；
3. 手动指定路径：
   ```bash
   node tools\connect-workbuddy.js --path "<WorkBuddy 目录>\resources\app.asar.unpacked\cli\bin\codebuddy"
   ```
4. 还是不行，直接走手动调用——功能不受影响，别在这上面耗时间。

### 4.2 常见报错对照

| 现象                                | 大概原因                      | 怎么办                          |
| --------------------------------- | ------------------------- | ----------------------------- |
| 脚本说「未找到 codebuddy」               | WorkBuddy 装在非常规位置       | 开 WorkBuddy → 设置里看安装目录，用 `--path` 指定 |
| `Authentication required`，但退出码为 0 | 独立 CLI 未取得有效登录身份 | 先解决受支持的 CLI 登录；本机桌面版退出/运行时均复现，不能只靠打开桌面版解决 |
| `Cannot find module '../dist/codebuddy'` | 内置普通入口回退到未随包提供的产物 | lite 路径可启动但仍需认证；不要修改安装目录，见直连排查结论 |
| 试跑超时（15 秒无输出）                    | 网络代理干扰，或没登录               | 关掉系统代理重试；确认已登录                 |
| 试跑报 `instanceof is not callable` | 代理配置让内部初始化崩了              | 同上去掉 `http_proxy` 等环境变量再试       |
| 反复试跑都是「超时无响应」（干净环境也一样） | 原因需实测，不能直接归因为桌面会话锁 | 2026-10-23 本轮未复现挂死，桌面开/关均快速返回未登录；先记录 Node、环境、stdout/stderr 和超时证据，避免反复消耗额度。仍不可用时走手动调用 |
| 之前好的，WorkBuddy 升级后断了            | 内部路径改了                    | 点「重新检测」；无效就改手动调用           |
| 批到一半全失败                          | 额度用完 / 登录掉线               | 看 WorkBuddy 里是否提示额度不足            |

最后一行那个「额度用完」值得单独说：**用老师自己的额度批 45 份作业，可能一次就把当月免费额度用掉大半。**批之前平台会显示预计份数，老师自己判断要不要今天批完。

### 4.3 数据在哪，怎么备份

| 内容         | 位置                          | 备份方式                         |
| ---------- | --------------------------- | ---------------------------- |
| 名单、课程、签到记录 | `data\*.json`               | 复制整个 `data` 目录               |
| 批改原始文件     | `data\批改\<作业名>\`           | 同上                           |
| 签名密钥       | `data\.secret`              | **要一起备**，丢了旧签到码无法校验           |
| 连接配置       | `data\settings.json`        | 同上；换电脑后需要重新检测                 |

后台「系统设置」里有「打开数据目录」，老师自己就能找到。

## 5. 一句话总结

**GitHub 上是干净的项目（只有代码，没有名单）；老师在 WorkBuddy 里粘一段话，它就把项目装好、把连接建好；连上了用直批，连不上用手动调用，两条路通向同一张成绩表。**
