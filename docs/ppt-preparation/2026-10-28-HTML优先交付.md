本轮按用户最新要求撤回PPT.AI复制/打开网站方案；先前记录仅作历史，不再代表当前产品流程。不删除已有教学任务、PPTX、大纲或附件。

平台方式：填写要求 → 选择方式 → 生成大纲 → 确认大纲 → 制作HTML → 确认HTML → 导出PPTX → 检查交付。手动方式仍将任务交给WorkBuddy独立执行，固定提示词同步要求大纲、HTML和PPTX分别确认。

HTML阶段只使用文件读写工具，不加载重型PPTX制作skill、不执行Python。WorkBuddy交付`html-delivery.json`及每页完整HTML，平台验证并复制为不可变版本。实际页面经无脚本sandbox iframe呈现，图片/字体/样式须内嵌，阻止外链、脚本、表单与嵌入网页。页面按1280×720画布缩放展示，备注另列，支持对照页面填写修改要求、指定页修改与历史版本查看。

教师勾选已检查并点击“确认HTML，导出可编辑PPTX”后，服务端校验HTML版本、大纲哈希与教学要求修订号。转换轮次复制指定HTML原件供WorkBuddy读取，才加载现有固定版本PPT Master，要求保留文案、顺序、主要排版，生成原生文本框和图形。平台校验PPTX结构、页数及页面原生文字；这不能替代教师在PowerPoint中的排版及编辑性检查。HTML修改后清除确认，旧PPTX保留下载但不能冒充新版本交付。

两小时上限、稳定进度动画、展开活动保留、结构化大纲编辑、Element参考资料上传、新建课件空值修复均保留。本轮不自动重新发起失败任务，不扩大Shell权限，不调用真实模型或外站服务。

开发验证使用假CLI、独立临时目录和虚构课件，覆盖：禁止绕过HTML确认、要求/大纲变化使确认失效、指定页以外变化拒收、取消丢弃迟到产物、旧版本保留、实际HTML接口及安全响应头、真实前端点击处理、两小时和八步导航。真实模型端到端出片及浏览器视觉验收仍待验证；当前浏览器工具因本机资源路径初始化失败不可用，不用历史截图充当本轮证据。
