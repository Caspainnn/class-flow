# 四步教师流程

用户已确认本次界面方案。教师导航统一为：填写要求 → 选择方式 → 生成大纲 → 生成PPT。第三步包含大纲生成、检查、编辑和确认；第四步包含课件制作、逐页预览、修改、历史、文件导出和课堂检查。手动方式也沿用相同四个名称，外部制作/导回说明留在页面内部。

界面以PPT、课件和课件版本描述成品，不将HTML制作、HTML确认或PPTX导出拆成顶部步骤。后台仍保留原有outline/html/html-modify/export阶段及版本、大纲、教学要求修订校验。点击“导出可编辑PPT”就是明确选择导出当前版本，无需再勾选独立的HTML检查框；这是用户对按钮方案的授权落地，并未绕过服务端确认门禁。

导出进行中继续展示真实课件预览，按钮所在的独立卡片显示局部进度及红框取消入口；沿用确认弹窗和稳定进度组件。失败/取消后在卡片内说明原因并重试，顶部仍停留在“生成PPT”。已导出的文件下载与“检查后，再带进课堂”保留。

“上一步”仍在内容底部左侧；从生成PPT可回到大纲编辑，之后可回到方式选择。只查看大纲后原样保存不再调用更新接口，避免无改动却使已有课件确认失效。存在修改时仍按既有未保存保护与版本规则处理。

## 开发验证

前端状态检查覆盖四步映射、按钮明确提交当前版本、导出保留预览、失败局部重试、不展示HTML术语、上一步回到大纲、无改动大纲保存不写入，以及原进度展开状态。服务端HTML确认门禁回归继续通过。

浏览器在3012隔离平台读取上一轮虚构20分钟课件，验证四步导航、实际预览和回到大纲；另创建明确标记的独立UI样例检查未导出按钮，不发起模型。正式教学数据和上一轮真实联调任务未改动。本轮仅修改静态界面，无需重启服务；刷新正式页面即可加载。
