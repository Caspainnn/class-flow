# 更新课件正式集成

用户已确认将更新模式接入正式项目，复用四步：填写要求、选择方式、生成大纲、生成PPT。更新原型后续的独立方案步骤不迁入正式流程。

## 使用

新建课件，填写基本要求并上传PPTX参考资料，显式选择“更新课件”。多份PPTX时选择要更新的原稿，其余作为补充资料；独立选择视觉模板。关联课程和视觉风格常驻主表单，补充要求仅保留自由文本框。手动交接保留复制/下载操作，但不展示prompt正文。

默认保留原页数、页序、主要正文、例题答案、数据、公式、表格、引用和必要图片。指定不同页数时，在原有大纲界面确认拆合页方案；每页显示来源原页码，编辑时可调整映射，但不能遗漏原页。大纲描述是简短审阅信息，制作读取完整原稿，不从短大纲重新写课。

## 实现与边界

- 任务持久化creationMode（默认create）、sourceFileId；源ID必须属于该课件且为PPTX。切换模式/原稿使大纲与成品确认失效；移除所选原稿回退新建模式，原历史版本保留。
- 原稿预处理用现有安全PPTX包校验，提取逐页文字、备注、完整页面XML、关联图表/SmartArt/备注等XML、媒体；用本机PowerPoint输出每页真实截图。截图和模板有独立目录/缓存，不互相覆盖。
- 原文件只读保留。外部链接不下载，无法直接读取的嵌入二进制对象交给模型明确标记待核对，不允许猜写或声称完全保留。
- 自动交接按阶段使用更新保留约束。大纲待教师整体确认，之后仍逐页串行生成HTML与演讲稿；逐页修改不改变其他页面。最终只转换已确认HTML为可编辑PPTX。
- 更新模式不新增网上配图，保留原稿必要图片；普通新建仍沿用最多一张平台外部配图规则。更新HTML单页上限28MB、总页面80MB、含源文件总计100MB，以容纳原图base64；普通新建仍为单页1MB/总页面20MB。超限报告失败，不默默删除图片。最终PPTX仍受现有20MB产物限制。
- 原稿截图准备失败时不启动模型；取消或超时后不启动后续子进程、不发布迟到产物。模型语义保留质量仍须教师逐页核对，不能将格式/映射测试视作内容100%保留证明。

## 指定页数与原页数不同的处理修正

实测：更换为15页原稿后，任务仍设置目标5页。模型将“先提出方案，不执行合页”误解为返回15页一对一大纲，仅在objective描述5页替代方案，触发页数校验。修复为：指定目标页数时，outline.pages必须恰好目标项数，各项sourcePages覆盖全部原页；该大纲本身即待确认的拆合页方案，只有教师确认后才制作。页数留空才默认一原页对应一新页。不自动清空用户设置或删内容凑数。

大纲失败页增加“调整课件要求”入口；表单显示原页数及目标页数，页数不符错误说明重试或清空页数的选择。隔离测试覆盖15页→5页的完整映射通过、错误15项拒绝、专用提示词及原新建流程。本轮未再次调用模型，未修改用户当前5页目标。

## 页数差异确认

更新模式点击“下一步”时，本机先验证PPTX并读取真实原稿页数，不调用模型。原稿与填写目标相差5页及以上时，使用原生确认弹窗：返回修改、按原稿页数、按目标页数。说明目标更少会精简/归纳/合并，目标更多会扩充/解释/拆分，之后仍需确认大纲。

选择原稿时清空指定目标，保持内容保留策略；选择目标时持久化pageCountPolicy=adapt及原稿ID、原页数、目标页数的确认标记，大纲和逐页制作提示词获得有范围的内容精简/扩充授权，仍保护核心知识、公式数值和答案正确性，不编造事实。更换原稿/模式/目标页数使确认失效；服务端拒绝过期选择，也拒绝跳过大差异确认直接调用手动或自动制作。保存草稿不弹出此确认；关闭/ESC不选择任何策略、不启动制作；失败留在弹窗可重试。

验证：check-ppt-page-count-choice.cjs使用15页虚构PPT，覆盖实际页数提取、阈值恰好5页、收缩/扩充提示、原稿/目标持久化、低于阈值继续、确认后不重复弹出、修改目标后重新确认、过期选择拒绝和服务端旁路阻止。前端测试执行实际saveForm代码，未进行本轮浏览器原生弹窗操作或模型出片验证。相关update-integration/new-task/service回归通过，独立代码复核未发现重要问题。
