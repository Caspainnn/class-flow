# 更新课件大纲：JSON报错根因与修复

## 现象与根因

更新课件生成大纲时报“制作未完成：Unexpected end of JSON input”。本次日志证据为CLI最终result.is_error=true，errors含“Max turns (30) exceeded”，且没有outline.json。平台仍从没有JSON的文本提取空字符串并JSON.parse，遮蔽了真正原因。

原稿63页；原source-content.json为516433字节，input.json为546782字节，重复携带各页关联图谱。模型读取大文件遭截断后反复补读单行，最终耗尽30轮，没有交付大纲。并非上传PPTX损坏，也不是2小时超时。

## 修复

- 完整原文、备注、媒体与关联XML索引保存为独立page-N.json，仍保留原PPTX与真实截图。大纲读取紧凑manifest及每10页一批摘要，制作时按来源映射读取完整详情。
- 摘要最多1600字符/页，标记截断；摘要不能作为制作内容替代原文。无文本页必须保留并标记待看图确认，不能擅自删除。大纲阶段不要求逐页查看全部截图/展开关联XML；这些在逐页制作阶段处理。
- 更新大纲只给模板布局ID/名称/区域类型轻量索引，不读取完整几何结构。轮次预算按摘要批次数调整；两小时总期限不变，无自动重试/额外调用。
- CLI调用轮次耗尽有专门诊断，保留原稿与要求；缺失/空大纲、截断JSON分别给可理解提示，不暴露解析器异常。历史大日志使用有界尾部读取，也能识别真正错误。

## 验证

同一原稿仅回放本地预处理，复用已存在截图，不调用模型、不修改正式任务：63页、7批摘要，manifest10088字节，最大批6353字节，全部详情文件保留。实际模型重跑质量仍待验收。
