## 1. 建议与决策摘要

建议把这个板块做成“老师掌控内容、系统协助排版与生成”的课件工作台。以一节课为单位，保留两个明确的人工确认点：**确认教学大纲**、**检查成品后标记可上课**。不把老师带入复杂的智能体配置流程。

推荐主线：**资料与课时要求 → 可修改的大纲 → 逐页内容和讲授备注 → 选择教学模板 → 可编辑PPTX → 检查、修改、下载**。大纲确认后即可产出初稿，不要求老师逐页点击批准；逐页修改集中在同一个工作台。

建议第一版采用 **WorkBuddy/CodeBuddy生成结构化教学内容 + 平台固定模板生成PPTX**。另保留手动内容编辑及手动WorkBuddy成品导入。理由：目前平台的独立CLI调用链存在可复用代码，但登录、端口、技能可见性和实际出片尚未完成当前机器验收；固定渲染器把“能生成文本”和“能交付PPTX”分开验证。

本机已经找到腾讯文档团队的 `workbuddy-pptx` 原生技能，它是值得验证的增强路径，不应忽略；但**安装文件存在 ≠ 当前独立CLI可调用 ≠ 已交付合格可编辑PPTX**。如后续验证证明它明显优于固定模板，可通过相同产物接口增加原生引擎，不重做课程、任务与版本模型。

三项待用户审查的主要选择：推荐上述混合路径；第一版采用受控教学模板和内容级编辑；PDF扫描件/OCR、任意旧PPT无损美化、学校模板自动适配与自动生图后置。

### 3.1 skill长期复用方式

skill是给智能体的工作指令与辅助资源，并非天然可直接HTTP调用的PPT服务。长期复用依靠**有许可的固定版本 + 固定输入输出协议 + 可测试的工具**，不能依靠安装后由模型自行发挥。

推荐将教学内容协议和平台渲染器作为自己的实现；未来如需要，可另编写本项目原创的教学课件skill，封装已批准的课时规则、JSON字段与模板ID，不改写或转抄受限skill。该skill不是第一版必需依赖，本阶段不创建。

CodeBuddy官方支持项目`.codebuddy/skills/`和用户`~/.codebuddy/skills/`，见[技能系统](https://www.codebuddy.cn/docs/cli/skills)。后续可将原创或许可允许的skill及其资源随隔离任务包部署，明确指定使用并记录版本；**当前CLI 2.173.0的实际加载机制仍须验证**。不得只靠description自动命中保证流程；后端照常验证输出。WorkBuddy桌面可在技能页安装/上传并在对话使用，见[官方技能管理](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Skills-Market)。两者的安装位置、启用状态和宿主工具不视为共享。

依赖只在正式实现获批后安装，锁定具体版本与来源，带许可证清单；不把当前机器绝对路径和个人账号写成可分发配置。字体、照片、图标、学校模板需分别确认使用范围；默认采用系统可用字体与原创图形，不把未经许可字体打入发行包。

## 4. 方案取舍

| 路径 | 优点 | 代价与风险 | 建议 |
| --- | --- | --- | --- |
| A. 平台直接调WorkBuddy原生PPT技能 | 现成视觉设计、逐页校验与编辑流程，潜在审美上限高 | 当前平台用独立CLI；托管工具、技能发现、宿主预览和登录依赖尚不通；缺少已验证对外契约 | 后续限量验证，验收通过再接入 |
| B. 结构化内容 + 固定教学模板 + 平台PPTX | 易落地到现有Node服务，人工可编辑内容，版式和产物可复现，AI失败仍能继续 | 初期自由视觉设计有限；浏览器预览与Office实际呈现有差异 | **第一版推荐** |
| C. 全手动交给WorkBuddy/其他办公工具 | 平台改动少，能直接利用桌面技能 | 老师需切换应用，进度不可自动跟踪，导回后不能无损同步平台内容 | 保留为保底，不作为唯一主线 |

没有推荐“让模型自由输出JS/Python并在平台执行”：它会把内容生成问题变成任意代码和环境管理问题。也不采用全页生图作为主格式：图片中的文字、例题和图表不便于老师临上课修改。

## 5. 适合课堂的工作流与第一版范围

### 5.1 四个工作区

1. **资料与要求**：选现有课程，写本课主题、学生基础、课时、教学目标；上传/粘贴材料。目标是“学生下课后能做什么”，不自动读取学生姓名和成绩。课程只提供id/名称等必要背景。
2. **教学大纲**：提出导入、讲解、例题/练习、总结的建议顺序；每段显示目标、预计分钟和页数。允许删除、增补、排序，老师点击“确认大纲”。课时和页数不硬绑定；材料不足须明确提示。
3. **课件编辑**：大纲确认后生成整份初稿；左侧页列表，中央页面示意，右侧内容/版式编辑。课件正文、教师备注、练习答案分开；答案默认放教师备注或独立讲评页，禁止无提示混入学生练习页。
4. **检查与下载**：列出排版和内容待核对项，下载PPTX/内容大纲/任务包，查看历史版本。老师检查后“标记可上课”；下载不等于审阅通过。

成熟流程的借鉴：Microsoft强调先组织资料结构并沿用模板；WorkBuddy本机技能把内容逻辑、视觉设计和逐页检查分开。本方案把这些做成教师可见的检查点；不让教师在八个连续表单之间往返。

DOCX/PDF解析库在正式阶段选择固定版本并复核许可；现有依赖尚不能覆盖该范围。第一版若解析器验收未过，该格式显示“暂不支持，请粘贴内容”，不静默传原始文件给AI或伪报成功。复杂公式课件可用老师上传的清晰公式图片，并标明该对象不可文字编辑；不阻止普通课件上线，但不得宣称复杂公式能力已完成。

交付口径：DOCX正文和文本PDF属于本提案第一版的必验项。可以先交付文本模式供阶段验收，但这两种解析未通过时，第一版只能记录为部分完成，不能以粘贴保底替代P03通过；若要删减格式范围，需用户另行确认。

### 5.3 页面与导航

- **列表**仍在`/preparation?type=ppt`：标题“PPT制作”，课程筛选、搜索、任务列表、右上角“新建课件”。列表显示课程、主题、更新时间、草稿/待确认/生成中/待检查/可上课/失败，主操作“继续编辑”。
- **任务**使用同一路由查询参数`&task=<id>&step=outline|edit|deliver`，避免新增外壳路由白名单。新建为简洁表单，资料上传后进入大纲；编辑与检查属于同一任务。
- 保留workspace、shell导航机制；内容样式限定在`.ppt-page`，不改侧栏全局字体、按钮、间距。未保存修改接入`appCanNavigate`；查询参数和前进后退同步。
- 单页改写显示差异再“采用/保留原稿”；不默认重写锁定页。错误在具体操作附近显示，统一toast和内联确认，不用原生alert/confirm/prompt。
- 390宽度页列表折为抽屉、编辑器上下排；1280宽度保证主操作和当前步骤清晰。键盘能完成上传、页排序替代按钮、保存与确认；对比度与焦点可见。
- `/workbuddy`继续作为统一设置入口，分“连接”“作业批改”“PPT制作”；连接复用，PPT有独立模型/超时配置，默认继承模型且明确标识。后台不自动运行付费探测，显示“上次验证时间”。

## 6. WorkBuddy调用、原生路径与手动保底

### 6.1 推荐平台路径

浏览器提交生成阶段 → 服务端创建job/input快照 → CLI仅生成大纲或页面JSON → 严格校验 → 作为候选稿让老师采用 → 本地受控渲染器生成PPTX → 校验产物 → 下载。

复用现有“配置路径 + spawn + 隐藏窗口 + 日志 + 轮询”的模式，不复制批改业务。新增PPT provider适配器，后续再考虑公共抽象；不在此阶段重构批改模块。

使用官方[无头模式](https://www.codebuddy.cn/docs/cli/headless)已支持的命令思路，具体参数先按安装版本离线帮助核对。首选文本输出、无工具调用（现有probe已用`--tools ''`），把已确认且长度受限的材料片段放输入，解析严格JSON或单一JSON代码块。不要求CLI写PPTX，不给Bash执行模型代码，不从回复中的链接或路径自动下载文件。结构化协议不是宣称当前CLI必有JSON schema约束开关。

输入预算与Windows传输：建议每次调用总输入不超过24,000个UTF-16字符（含指令、大纲与片段），并根据固定模型的上下文预算进一步收紧；字符上限不等于token上限。长材料先在本地按来源分段，由老师选入，超预算列出未纳入片段并要求缩小范围，不静默截断，也不把100MB上传量当作模型输入量。长输入通过子进程stdin传输并关闭输入流，不拼进`-p`命令行；官方文档支持stdin，但当前2.173.0兼容性须验证。若不兼容，关闭长输入自动调用并提示手动路径，不退回无限命令参数。初稿可按章节分job生成，界面事先显示调用批次数；单页改写只带该页及必要上下文。

任务cwd独立，传参用数组且`shell:false`，清理子进程继承的已知干扰变量只作用于子进程；不更改系统环境或账号。cwd和`--add-dir`不是安全沙箱：若未来引擎需要文件/命令工具，须另行限定权限并验证隔离，不能宣称单靠工作目录保护了全机。

只发送老师选中的课件资料；首次AI操作明确显示材料将交由所选模型服务处理及可能计费。课堂签到数据本地存储不代表AI路径离线；正式实现时须同时修正README中“所有数据不联网”的过宽描述。密钥与凭据不进入提示词、前端和日志。

### 6.3 手动路径必须能真正接续

平台导出ZIP任务包：教学要求、大纲、逐页内容、老师选定的资料副本、素材来源清单、输出要求与内容JSON模板；包中不含名单/成绩/账号配置。老师在WorkBuddy新任务中指定该目录和PPT技能，使用已确认大纲生成或修改课件。

导回提供两种方式：

- `content.json`：通过schema校验后预览差异，老师采用为新版本，再由平台渲染；可继续单页编辑。
- `.pptx`：检查包结构、页数、文件大小与危险外部关系后作为“外部成品”新版本保存下载；不声称已提取为可编辑平台内容，不覆盖原内容源。可附预览PDF/图片但作为单独文件检查。

外部成品不可假装与平台JSON一致：在PowerPoint/WorkBuddy改过的文件，平台不会自动吸收逐对象修改。继续编辑时明确选“从平台内容继续，生成另一个版本”或“继续外部编辑并再次导入”。AI不可用时老师还可直接编辑平台正文并本地导出PPTX；手动WorkBuddy本身也依赖可用账号/工具，不能承诺它永远成功。

## 7. 数据与接口草案

以现有本地JSON架构落地，无需新数据库。所有新增持久化位于`store.DATA_DIR`，不把PPT模块路径硬编码回真实data目录。

```text
<DATA_DIR>/ppt-tasks.json                   # 任务索引；服务端串行更新
<DATA_DIR>/ppt/<taskId>/sources/            # 原始材料，只读引用，随机assetId
<DATA_DIR>/ppt/<taskId>/extracted/          # 文本片段、页/段落定位和hash
<DATA_DIR>/ppt/<taskId>/versions/<versionId>/
  content.json                             # 不可变内容快照
  manifest.json                            # 引擎、模板、字体、来源与文件hash
  deck.pptx                                # 生成成功并校验后才存在
<DATA_DIR>/ppt/<taskId>/jobs/<jobId>/        # 输入、状态、候选输出、截断日志
```

| 实体 | 核心字段 |
| --- | --- |
| Task | id、courseId、courseNameSnapshot、title、lessonMinutes、audience、goals[]、requirements、currentRevision、outlineApproval、currentVersionId、readyVersionId、createdAt、updatedAt、deletedAt |
| Source | id、originalName、storedName、mime、size、sha256、extractStatus、locatorType、selectedChunkIds、parseWarnings；原文位置不可编造 |
| Outline | sections[{id,title,goalIds[],minutes,slideIds[]}]、confirmedRevision/hash、confirmedAt；改结构后确认失效 |
| Slide | stable id、sectionId、layoutId、title、blocks[]（受控text/image/table/chart）、speakerNotes、answerPlacement、sourceRefs[]、locked、revision；禁止任意HTML/JS |
| Version | id、parentId、contentHash、outlineHash、templateId/version、renderer/version、provider/model/skillVersion（已知时）、sourceHashes、createdBy、createdAt、origin(platform/external)、qc、artifacts[] |
| Job | id、taskId、stage、baseRevision、inputHash、idempotencyKey、provider、status、attempt、startedAt、heartbeatAt、finishedAt、errorCode、exitCode、warnings、candidateVersionId |

`outlineApproval`记录确认人操作和内容hash；任何会改变教学结构的修改使其失效。文字小改不强迫重走新建。修改上游材料或目标时提示影响，保留旧版本；正在运行的job绑定旧快照，不自动采用为当前稿。已标可上课的版本保持可下载，新草稿不能抹去它。课程删除沿用现有隐藏规则，课件索引不再列出；文件保留，不级联物理删除。

接口以`/api/ppt`为前缀，均仅本机教师可用，下载同样鉴权；请求写操作校验同源，不能仅凭loopback防跨站调用。下列为正式开发的契约草案：

| 方法与路径 | 行为 |
| --- | --- |
| GET /tasks?courseId=&q= | 分页/过滤索引 |
| POST /tasks | 建草稿，返回taskId、revision |
| GET /tasks/:id | 任务、当前内容、材料状态、最新job |
| PATCH /tasks/:id | 保存要求/正文/排序，携baseRevision，冲突409 |
| POST /tasks/:id/sources | 上传并创建抽取job；明确限制格式和大小，不把请求挂到解析结束 |
| DELETE /tasks/:id/sources/:sourceId | 取消后续引用，旧版本保留hash与已有快照 |
| POST /tasks/:id/outline/confirm | 验证revision并记录确认hash |
| POST /tasks/:id/jobs | stage=outline/content/rewrite-slide/render；指定baseRevision、目标slideId、provider、幂等键，202返回jobId |
| GET /jobs/:id | 状态、阶段、可读错误；不伪造百分比 |
| POST /jobs/:id/cancel | 幂等取消，停止所属子进程树，不杀其他Node/WorkBuddy |
| POST /jobs/:id/accept | 把合法候选稿采用为新revision；旧base冲突409，不覆盖老师新修改 |
| GET /tasks/:id/versions | 历史及检查信息 |
| POST /tasks/:id/versions/:vid/restore | 从旧版复制为新草稿，不覆盖历史 |
| POST /tasks/:id/ready | 绑定明确versionId，要求文件校验完成及老师确认检查 |
| GET /tasks/:id/artifacts/:artifactId | 服务端ID映射下载；不接收任意绝对路径 |
| GET /tasks/:id/manual-package | 受控打包；记录材料范围与内容revision |
| POST /tasks/:id/import | 内容JSON或外部PPTX；检查后显式采用 |
| DELETE /tasks/:id | 运行中先取消；软删除，内联二次确认 |

第一版不支持客户端传CLI命令、程序路径或任意引擎参数。统一设置维护连接，PPT页只选已配置的provider；设置更新不改变既有job快照。

## 8. 失败、重试、版本和质量

### 8.1 任务规则

- 全局CLI并发初始为1（含批改协调），防本机资源与历史单实例冲突；仅有PPT队列不等于解决与批改的冲突，正式阶段须给两条启动入口增加最小共享锁。任务级同一阶段不重复启动。
- job状态：queued → running → validating → succeeded；另有failed/cancelled/interrupted。succeeded表示候选产物成功，**不等于老师已确认可上课**。页面业务状态独立派生。
- 大纲/单页改写初始超时120秒，整份内容300秒，单次本地渲染120秒，均为待实测调整的提案；不继承批改单份60秒或乘以学生数。
- 自动重试仅用于本地无付费且幂等的临时文件操作，最多1次；**模型失败不自动二次计费**，老师看见失败原因后手动重试。重试新建job，使用同一输入快照；修改输入则创建新任务尝试。
- 程序启动时扫描未终态任务并标interrupted，不自动重放模型请求；保留最后成功版本。进程退出0、stdout说“完成”或找到旧PPTX都不能作为成功判据。
- 取消/超时后终止已确认所属的进程树、等待关闭并封存输出；拒绝迟到结果自动采用。任务目录与jobId隔离，避免旧文件误报本次成功。
- 错误码区分AUTH_REQUIRED、PROVIDER_BUSY、DEPENDENCY_MISSING、TIMEOUT、INVALID_CONTENT、RENDER_FAILED、QC_FAILED、CANCELLED、INTERRUPTED；按原因给重试/去设置/手动操作入口，不把原始stderr或密钥暴露给前端。

### 8.2 质量标准

| 层次 | 自动检查 | 人工检查/边界 |
| --- | --- | --- |
| 输入 | 类型/大小/解压限额、防路径穿越、重复hash；解析失败不进入内容生成 | 老师检查提取片段是否代表原文；扫描件不猜内容 |
| 教学 | 目标与section/页面关联、课时总和、缺失例题或练习提示；来源引用存在性 | 事实、公式、例题答案、难度和节奏由老师核对；有引用不等于结论正确 |
| 视觉 | 字体、边界、文本容量、色彩对比、图片尺寸、标题/页码完整；溢出时分栏/拆页候选，不无限缩小 | 初始正文建议24pt以上、标题32pt以上；实际投影可读性人工确认。图注例外但需可读 |
| 文件 | ZIP/OOXML必需部件、relationships、页数、文本/图表/备注存在、产物hash | 使用PowerPoint实际打开且无修复提示，修改文字/形状/表格/图表后另存；图片仍为图片 |
| 安全与隐私 | 禁止模型代码执行、阻断任意路径/外链引用、宏格式不接收；ZIP条目数和膨胀率限制 | 外部文件不能由自动检查保证绝对无害；不执行宏或自动加载远程资源 |

第一版的浏览器页面是示意预览，不验证Office字体回退与真实换行。正式验收必须在实际PowerPoint逐页查看；PDF/缩略图的自动化渲染作为后续适配能力，不能因缺少LibreOffice静默假装已预览。即使可下载，未做实机检查的版本标“待检查”。
