## 1. 目标形态

**双击一个图标 → 主界面 → 点「开始上课」→ 选课时 → 投影出二维码 → 学生扫码签到。**

老师这一侧只有三个动作：双击、点开始、选课时。之后不需要再操作任何东西。

### 1.1 启动方式（已定）

- 桌面放一个 `课中签到.bat`（或快捷方式），双击后：
  1. 后台启动本地服务（端口 3000）
  2. 自动用浏览器以**独立窗口**打开主界面
  3. 关掉窗口即退出程序（同时结束服务进程）
- 不需要装 Node、不需要命令行、不需要证书（纯动态码模式）
- 数据全部落在本地 `data/` 目录，拷走这个文件夹就是完整备份

### 1.2 主界面（三个按钮）

| 按钮 | 做什么 |
|---|---|
| **开始上课** | 进课时列表 → 选一个 → 直接进投影签到页 |
| **后台设置** | 数据看板、题库管理、课时管理、名单、系统设置 |
| **退出程序** | 关闭窗口并结束服务（第三个按钮，如果你想要的是别的功能，告诉我换掉） |

## 2. 两个关键参数已按你的要求改

### 2.1 动态码 3 秒刷新

- 二维码**每 3 秒换一次**（视觉上就是 3 秒变一次）
- 但服务端**接受最近 4 片令牌**，也就是实际有效期 **12 秒**
- 这样做是为了解决一个硬冲突：学生从抬头看屏幕到扫完，通常要 2–3 秒，加上网络 0.3 秒。如果令牌真的只活 3 秒，会有三到五成的人扫到刚过期的码，课上变成一排人举手。
- 代价要说明白：**截图转发仍有约 12 秒的空隙**，比原来的 30 秒短，但不是零。
- 投影上会加一个倒计时环，让「在变」这件事看起来是有节奏的，而不是闪。

### 2.2 每节课 1 道题（已定）

- 题库按课时绑定，一个课时可以存很多题
- 开课时按设置**随机抽 1 道**（默认），也可以指定某一道
- 学生答完这道题即完成签到

### 2.3 其他参数不变

| 参数 | 值 | 说明 |
|---|---|---|
| 签到窗口 | 90 秒 | 窗口内算准时 |
| 迟到补签 | 10 分钟内 | 自动记迟到，不用老师判断 |
| 课堂码（降级） | 30 秒一换，60 秒内有效 | 扫不出来时手输 |
| 答题时限 | 120 秒 | 扫码后慢慢答，不影响准时判定 |

## 3. 数据模型

全部存本地 JSON 文件，放在 `data/` 下，一次写入用「临时文件 + 改名」保证不写坏。

```
students.json      [{ id, name, classId }]
courses.json       [{ id, name, classId, term }]
banks.json         [{ id, name, courseId, questions: [Question] }]
lessons.json       [{ id, courseId, title, date, bankId, questionId|null }]
sessions.json      [{ id, lessonId, courseId, startedAt, endsAt, records: [Record] }]
settings.json      { codeRefreshMs, tokenGrace, windowMs, lateGraceMs, ... }

Question  { id, type: 'single'|'judge', text, options[], correct, explain }
Record    { studentId, name, status: present|late|absent|leave, claimedAt,
            submittedAt, answer, correct }
```

关系：**课程 → 课时 → 题库**。课时是「第 12 周 · 周三 3–4 节」这种粒度，一个课时绑一个题库，因此开课时自动就知道该出哪批题。

## 4. 页面清单

| 路径 | 谁看 | 内容 |
|---|---|---|
| `/` | 老师 | 主界面：三个大按钮 |
| `/lessons` | 老师 | 课时列表（本周在前）+ 新建课时 |
| `/live/<lessonId>` | 投影 | 二维码、课堂码、题目、到课数、缺勤数、倒计时 |
| `/admin` | 老师（仅本机） | 五个 Tab：数据看板 / 题库管理 / 课时管理 / 名单 / 系统设置 |
| `/s/<sessionId>?t=<token>` | 学生 | 学号 + 一道题 + 提交 |
| `/join` | 学生 | 输 4 位课堂码（降级通道） |

### 4.1 后台只允许本机访问（已定）

学生手机连的是同一个 Wi-Fi，能访问到服务，但访问 `/admin` 和所有写接口时，服务端检查请求来源是不是 `127.0.0.1`。不是就返回 403。

这样不需要密码，也不会出现「学生打开后台把题库删了」。

### 4.2 后台四个 Tab 各自要有什么

**数据看板**
- 今日 / 本学期到课率
- 最近 5 次课的签到曲线
- 本次课：到课数、迟到数、缺勤名单、题目选项分布、正确率
- 一键导出 CSV（签到明细 / 答题明细）

**题库管理**
- 按课程分组，显示题目数与最近使用时间
- 新增题目：题型（单选 / 判断）、题干、选项、正确答案、解析（可选）
- 批量导入：粘贴文本，一行一题，格式 `题干|选项A|选项B|选项C|选项D|正确答案字母`
- 编辑、删除、复制到其他题库

**课时管理**
- 新建课时：课程、标题、日期、绑定题库
- 列表显示：课时名、题库、已上过几次、到课率
- 「复制上周」按钮，省得每次重填

**名单**
- 手动添加 / CSV 导入（学号,姓名）
- 显示连续缺勤次数

**系统设置**
- 码刷新间隔（默认 3000ms）
- 令牌宽限片数（默认 3 片）
- 签到窗口（默认 90s）
- 抽题方式（随机 / 指定）
- 数据备份（导出整个 data 目录为 zip）

## 6. 实施顺序

1. **数据层**：JSON 读写、原子写入、默认数据（示例课程 + 12 道题 + 47 人名单）
2. **主界面 + 课时选择**：三个按钮、课时列表、新建课时
3. **投影签到页**：3 秒换码、12 秒有效、题目展示、到课数、倒计时
4. **学生端改造**：按课时取题、提交入库
5. **后台**：题库管理 → 课时管理 → 数据看板 → 系统设置
6. **启动脚本**：`课中签到.bat`，双击起服务并开窗口
7. **验收**：跑一遍完整流程，导出一次 CSV

---

## 7. 验收标准

- 双击能起，关窗口能退，不留后台进程
- 从点「开始上课」到投影出现二维码 ≤ 2 次点击
- 手机扫码到显示「已签到」≤ 15 秒
- 3 秒换码时，正常扫码成功率 ≥ 95%（这是选 12 秒窗口的原因）
- 题库里加一道题，开课后能被抽到
- 后台导出 CSV 能用 Excel 打开，中文不乱码
- 学生手机打不开 `/admin`
