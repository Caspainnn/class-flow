## 3. 必须保持不变的部分（这是产品的核心，别动）

动态码签到机制**完全沿用现实现**，不要重写：

- `token = HMAC-SHA256(SECRET, sessionId + ':' + slice).slice(0,12)`，`slice = floor(now / 3000)`，码**视觉 3 秒刷新**
- 时间片宽限：接受最近 4 片 → **令牌有效 12 秒**
- 两步兑换：`/api/claim`（token 或 4 位课堂码 → ticket，TTL 120s）→ `/api/submit`（ticket + 学号 + 姓名 + 答案）
- **设备指纹**：cookie `ic_dev`（1 年）绑定 ticket。规则：一设备一课一票；ticket 与设备绑定，换设备提交拒绝。这是挡「一部手机扫两次帮别人签」的闸门，必须保留
- 签到窗口 90 秒，迟到补签宽限 10 分钟（超时后 claim 直接拒绝）
- 权限隔离：除 `/s/`、`/join`、`/api/claim`、`/api/submit`、`/qr.svg`、`/api/ping` 外，其余路由**只允许回环地址**（学生手机访问 `/admin` 返回 403）
- 数据写入：临时文件 + rename 原子写（`store.write`）
- **`confirm()` 在独立窗口会被静默拦截**——历史上「结束本次签到」点不动就是它导致的。新界面里不要依赖 `confirm()` 做关键流程

## 4. 数据模型改造

### 4.1 新结构

```
courses.json   [{ id, name, term, createdAt }]          # 课程
students.json  [{ id, name, courseId }]                 # 名单，按课程归属（去掉 classId）
sessions.json  [{ id, courseId, question, startedAt,
                  endsAt, closed, records[] }]          # 一次点名 = 一条记录
settings.json  { codeRefreshMs, tokenGrace, windowMs,
                 lateGraceMs, ticketTtlMs, activeCourseId }
```

`session.question` 是**快照**：`{ text, options:[...], correct:index }`。即使以后改题，历史记录不受影响。

`session.records[]`：`{ studentId, name, status:'present'|'late', answer:index|-1, correct:bool, claimedAt, submittedAt }`

### 4.2 废弃

- `lessons.json`、`banks.json` 整体废弃（用户明确「不需要题库」）
- 删除 `lessons.html`、`pickQuestion()`、`startSession(lessonId)` 的课时/题库依赖
- 会话已落盘的 `lessonId` 字段无害，`session.question` 自带快照，历史数据不会坏
- 若 `data\` 下已有旧文件，不要删，代码不再读写即可

## 5. 页面与流程改造

### 5.1 打开方式改浏览器

`课中签到.bat` 现在用 `--app=http://...` 起 Chrome/Edge 独立窗口。**改成默认浏览器打开**：

- 删掉 `--app` / `--user-data-dir` / `--window-size` / `/wait`
- 用 `start "" http://127.0.0.1:3000/`（走系统默认浏览器）
- 去掉末尾自动 `taskkill` 逻辑（浏览器关了服务还在，由页面上的「退出程序」按钮调 `/api/quit` 来停）
- `chcp 65001` 保留

### 5.2 老师主流程（三步，替换现在的 home → lessons → live）

**Step 1 选课程**（`home.html` 重做）
列出 `courses`，显示每门课名单人数。点一门课进入 Step 2。

**Step 2 现场出题**（新建 `compose.html`，替换 `lessons.html`）
- 顶部显示当前课程名 + 名单人数（可点「换课程」返回）
- 题干输入框
- 选项：默认 4 个（A/B/C/D），可增删，范围 2–6
- 指定正确答案（单选按钮，默认 A）
- 按钮「开始点名」→ POST 创建 session → 跳 `live.html`
- 附加：把最近出过的题存在课程下（`course.recentQuestions`，最多留 10 条）做快捷复用，点一下填入。这只是便利功能，不算题库

**Step 3 点名投影**（`live.html` 基本保留）
- 大二维码（`/qr.svg`，3 秒刷新）+ 4 位课堂码（30 秒换）
- 显示题干 + 选项（投影给学生看）
- 实时计数：已签 X / 应到 Y、迟到 N、答题分布、答对率
- 「结束本次点名」：即时置灰 + 遮罩，不做 confirm
- 结束后提供两个去向：**「再出一道题」**（回到 Step 2，同一课程开新一轮）、**「回主页」**

### 5.3 学生端（`student.html` 小改）

- 保持两步：扫码 → 填「学号 / 姓名 / 选择答案」→ 提交
- 学号+姓名按**当前 session 的 courseId 对应名单**校验，不匹配返回明确中文错误
- 提交成功页显示：姓名、状态、本题是否正确

### 5.4 后台（`admin.html` 重写，三个 Tab）

**Tab 1 数据看板（课程整体统计）**
- 选课程 → 该课程历次点名列表：日期时间、到课/应到、出勤率、答对率
- 出勤率趋势：按次画折线/柱状（纯 SVG 或 canvas 手写，不要引图表库）
- 每人累计出勤表：学号、姓名、出勤次数/总次数、出勤率、累计答对率，缺勤多的排前面并标红

**Tab 2 课程管理**
- 课程增删改（名称、学期）
- **名单管理**（按课程）：
  - 粘贴框：`学号,姓名` 或 `学号 姓名` 或 Tab 分隔，一行一条，支持全角逗号
  - **上传 xlsx/csv**：前端 `<input type=file>` 读成 base64 或 ArrayBuffer 传给服务端，服务端用 **exceljs 解析**（已装），取前两列作为学号、姓名，跳过表头；学号列按文本读取（防止长学号被转科学计数法）
  - 名单列表：可搜索、可删除单人、可清空
  - 显示「本课程名单 N 人」
- **签到数据导出**：
  - 按次导出：选某次点名 → xlsx
  - 按课程导出：整门课所有次合一张表（每次一个 sheet，或一张明细表加「点名批次」列——选后者，更好筛选）
  - **导出列顺序**：学号、姓名、题目、**提交答案**、**正确答案**、是否正确、状态、签到时间
    （「正确答案」是这次新增的，现实现只有「所选答案」，必须补）
  - 学号列 `numFmt='@'` 保持文本；冻结表头 + 自动筛选保持
- **数据保存位置**：明确显示 `<项目目录>\data`，列出各文件名和大小、最后修改时间，并提供「打开文件夹」按钮（服务端执行 `explorer <path>`，走一个 `/api/open-folder` 路由，仅限回环地址）。文字说明：数据本来就存本地，导出只是为了方便交给教务处，不是必须的

**Tab 3 系统设置**
- 码刷新间隔（默认 3000ms）、令牌有效片数（默认 3 → 有效 12s）、签到窗口（默认 90s）、迟到宽限（默认 600s）、ticket 有效期（默认 120s）
- 端口（改了需重启才生效，要写明）
- 数据目录路径（只读展示）

## 9. 已知的坑

1. **`confirm()` 在 `--app` 独立窗口静默返回 false** → 关键流程不要用它（改浏览器打开后仍有风险，统一不用）
2. **名单校验是硬闸门**：名单里姓名与学籍姓名不一致（生僻字、空格、繁体）会签不上。名单录入页要提示「姓名必须与本人填写的一致」，并去除首尾空格后比对
3. **学号被 Excel 转数字**：导出 `numFmt='@'`，导入时按文本读取
4. **后台进程被 IDE 回收**：在对话里用 Bash 起的 `node server.js` 会随任务被杀。自测时优先让用户双击 bat 启动，或用 `curl` 打一次接口确认存活
5. **端口占用**：3000 被占时启动会静默失败，bat 里应检测并提示
