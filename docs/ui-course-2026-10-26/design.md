# 课程管理交互原型

状态：用户已批准最新原型并要求正式实现。实现与本地隔离自测完成，用户验收待进行。正式页面为 /courses；详见 verification/acceptance.md。真实教学数据未变化。

## 用户偏好

以后工作台类原型优先使用HTML，重视字号、留白、配色、信息层级和响应式。图像生成仅用于需要探索视觉方向或制作图片素材的场景。

## 本轮方案

- 「课程与名单」改为「课程管理」。课程首页用卡片展示名称、学期、名单人数、签到记录数与准备状态；支持搜索、按学期筛选、新建及进入管理。
- 创建和管理使用不同界面：新建课程保留「基本信息 → 名单录入 → 确认完成」；已有课程进入高密度单页，顶部展示人数、签到次数、作业数量与准备状态，左侧集中维护名单，右侧编辑基本信息及删除课程，不再要求切换步骤。
- 新建入口仅保留首页右上角按钮，移除重复的新建占位卡片。
- 创建及管理的名单录入均默认展示上传表格；粘贴名单作为第二种方式保留。
- 管理页提供删除课程入口及内联确认，显示课程名称、名单和签到数量。原型删除仅移除内存中的示例卡片，刷新可恢复；正式删除的数据规则在接入业务时明确。
- 当前已有名称、学期、粘贴和表格导入名单；原型提出可选课程备注，待确认后决定是否增加存储字段。
- 名单可稍后补充，卡片显示「待录入名单」。当前原型不引入开课、结课或归档等新业务状态。
- 删除左侧「课堂准备」入口；「PPT制作」「教案制作」直接位于「课前」分组，仅展示规划中页面。
- 原型用内存中的虚构数据，刷新恢复。所有导航和步骤只用于审阅，不调用业务API、不保存文件、不会修改真实课程。

## 审阅重点

课程卡片与高密度管理页是否合适；新建三步流程是否自然；删除确认是否清楚。
