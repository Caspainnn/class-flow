# 问卷管理可点击原型

日期：2026-10-31。状态：原型制作与自测完成，待用户验收；尚未接入正式业务。

后续进展（2026-11-01）：用户已确认本原型验收通过，正式业务实现及隔离自测已完成。当前交付入口和正式验收见[正式交付与验收](正式交付与验收.md)；下文保留原型阶段的演示边界与检查记录。

本轮新增真实 WorkBuddy 初版生成：新建问卷 → WorkBuddy 辅助制作 → 填写调查需求 → 生成 → 查看并编辑初版 → 教师确认后设置发放。生成沿用本机连接设置，实际执行为 CodeBuddy CLI，仅允许文件读写，不启用 Bash。

创建流程现统一展示顶部步骤导航：WorkBuddy 为「填写基本信息 → 选择方式 → 填写需求与生成 → 审阅题目 → 预览发布」，手动为「填写基本信息 → 选择方式 → 编写题目 → 预览发布」。基本信息包括课程、匿名/实名和截止时间，进入后续步骤时保留。需求页不展示最近任务；生成完成自动进入审阅，不再停留在初版完成页，也不会自动发布。各步骤的上一步在内容底部左侧；审阅返回需求填写不会重新发起模型任务，返回再进入保留教师修改。未命名且尚未保存的手动输入在本页会话中暂存，关闭页面前应填写标题并保存草稿。

根据用户对电脑版拖动体验的反馈，题目排序恢复为卡片右上角的「上移 / 下移」，首题禁用上移、末题禁用下移；已移除拖动手柄和拖动事件。复制入口不恢复，删除保持红色文本和确认弹窗。量表编辑器仅保留两端含义输入，移除装饰性的1至5数字行；学生填写和手机预览仍保留实际量表选项。按钮排序回归已验证题目、选项及题目ID保持完整。

真实样例：http://127.0.0.1:3013/prototype/questionnaire.html#ai/7d871372f4a4ba598166985b 。虚构 GAN 课程需求用时48秒生成6题，已验证完整导入为草稿。点击「查看并编辑初版」才能带回浏览器；再次导入打开已有问卷，不覆盖教师修改。教师确认与发布尚待用户操作。

## 现在可以操作什么

1. 列表搜索、按课程和状态筛选、新建、复制、删除草稿。
2. 三步创建：填写问卷、设置发放、预览发布。单选、多选、1–5分量表、简答；题目编辑、复制、排序、必答设置和草稿保存。
3. 默认匿名，可选实名。设置课程、截止时间，查看手机预览；未保存离开时选择继续编辑、放弃或保存。
4. 模拟发布后显示演示二维码、复制演示链接、在新标签打开学生端。模拟学生提交后，通过浏览器本地存储同步教师端演示数据。
5. 停止、恢复回收、归档及取消归档。停止使用红框按钮和确认弹窗，保留已有答卷。
6. 匿名按份数统计，不显示回收率、未提交名单或身份明细；实名显示固定目标名单47人、提交36人、回收率76.6%及11人未提交。
7. 选择题分布、量表均值与分布、简答原文搜索、答卷明细。按选择题答案或提交时间筛选后，逐题分析与明细使用同一批答卷。
8. 可下载CSV演示数据，包含导出范围和筛选信息。匿名导出不附学号姓名列；文本做CSV转义及公式前缀防护。

## 演示方法

- 打开「本节课学习反馈 → 查看」，点击「打开学生端演示」，在另一标签提交；返回教师端点击刷新可观察回收量变化。
- 学生页面底部「原型演示状态」可切换网络失败、提交中、停止回收、截止、已提交、链接无效；它不是正式学生界面的业务功能。
- 实名样例默认已经结束，可先恢复回收。可用未提交身份：学号 `S037`，姓名 `示例学生37`。这些是合成名单。
- 需要回到初始样例时，点击教师页面右上角「重置演示」，确认后只重置本原型数据。

## 原型边界

- 演示问卷、名单、答卷使用合成数据；AI 初版则根据教师填写的需求真实生成。问卷存储键为 `inclass.questionnaire.prototype.v1`，只在当前浏览器和该端口下保存。生成服务只读取正式 `data/settings.json` 中的 WorkBuddy 连接配置，不读写真实课程、名单和答卷。
- 生成需求和任务结果保存在已被 Git 忽略的 `.tmp-questionnaire-ai/`，需求表单另用浏览器键 `inclass.questionnaire.prototype.ai-requirements.v1` 保存。任务历史在同一本机服务下共享，尚不提供正式多教师账号权限。重置演示不会清除生成历史或中断正在运行的任务。
- 本机演示二维码不等于正式课堂发放地址。学生手机扫描 `127.0.0.1` 不能访问老师电脑；正式开发才会生成局域网地址并配置对应公开填写入口。
- 公开页面只是原型静态资源，教师与学生共享的演示状态存储在浏览器中，不代表正式版本的权限隔离实现。
- 本轮导出为真实CSV，未伪装成XLSX；多工作表Excel是正式开发阶段的交付项。
- 匿名方式只限制同一浏览器的重复提交，不宣称严格一人一份；实名方式是名单核对，不是强账号认证。
- AI 仅用于起草题目；不对学生简答自动编造结论，不向真实学生发送消息或发放问卷。生成使用已登录账号额度；题目质量仍需教师审阅，不构成科学量表效度验证。

可复跑检查：

```text

node tools/check-questionnaire-ui.cjs
node tools/check-questionnaire-preview-http.cjs
node tools/check-questionnaire-ai.cjs
```

界面测试使用原型实际JS事件处理函数与隔离DOM模拟，覆盖创建、验证、发布、提交失败/成功、复制、未保存退出、停止及CSV等分支；不将其称为完整浏览器点击测试。

本轮 `cua_repl` 浏览器控制工具在初始化时报告内核资源路径不存在，重置后仍失败。因此采用独立无界面Edge截图检查桌面和390像素窄屏，尚未完成通过浏览器控制工具逐项点击的人工式验收。这一限制不影响打开原型供用户审查。

截图位于 `docs/questionnaire/prototype-review/`：列表、匿名分析、实名回收、编辑、设置、发布预览、学生填写及三个窄屏画面。

正式平台的导航、课程名单、学生端、问卷业务接口尚未修改。用户验收原型后，再按方案补齐正式功能和权限、数据持久化及并发校验。

结果分析已按用户要求移除教师标记输入、保存入口及依赖标记的主题统计；保留简答原文和搜索。原有浏览器数据中的历史标记不做破坏性清理。

首页统计卡片参考 [Ant Design Statistic](https://ant.design/components/statistic/) 和 [Tabler Dashboard](https://preview.tabler.io/) 的数字层级与图标组织：深蓝总览卡、状态色图标、统一单位及底部分隔说明。不加入虚构涨跌或趋势。原有计数与列表交互回归通过，桌面截图见 `prototype-review/metrics-redesign.png`。

学情分析的问卷数据看板原型入口：`#dashboard`，侧栏「数据看板」。展示课程筛选、已发布问卷量（含结束及归档、不含草稿）、实际正在回收量、累计答卷（不是去重人数）、单份问卷反馈分布和最近问卷；支持跳转完整分析。实名才显示回收率及未提交人数，零数据明确留空；不合并不同量表，不推断能力或预警。使用同一隔离浏览器状态，不修改 `xueqing/public/analysis.html` 和正式教学库；正式出勤与作业看板通过单独链接访问。正式问卷业务落地后还需把这些卡片接入既有课程看板并使用正式课程ID。课程筛选、匿名/实名和空状态脚本通过；截图见 `prototype-review/questionnaire-dashboard.png`。

实名问卷的「未提交名单」现与逐题分析、答卷明细一样在结果视图内以表格展示，不使用弹窗；发放与回收页也直接展示该表格。按发布时完整目标名单减去已提交学生计算，不受答卷筛选影响；全部提交时展示空状态。匿名问卷不展示该表格。

逐题分析同时展示柱状图和环形图，电脑端左柱状图、右环形图，窄屏自动上下排列，不再提供图形切换按钮。适用于单选、多选和量表。单选及量表环形占比以本题有效作答为分母，未答不纳入；多选环形图以总选中次数为分母，明确提示不是人数占比。多选柱状图仍按有效作答份数计算，各项之和可超过100%。图例保留全部选项、计数及比例，零值不产生扇区；两张图使用同一批筛选后的数据。
